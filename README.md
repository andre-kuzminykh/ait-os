# Andre AI — Telegram-бот для анализа AS-IS процессов

Telegram-бот, который помогает компаниям описать текущие бизнес-процессы через интервью, сгенерировать AS-IS страницу и выявить возможности автоматизации.

## Возможности

- Главное меню с кнопкой «Процессы» в бургер-меню Telegram
- Создание процессов через кнопку «➕» с вводом названия
- Пошаговый прогресс при анализе (редактирование одного сообщения)
- Эффект «печатающей машинки» при отображении распознанного текста
- Автоматическое удаление сообщений пользователя и ассистента (чистый чат)
- Просмотр процесса: продолжить заполнение или открыть AS-IS/TO-BE
- Интервью по процессу через текст или голосовые сообщения
- Автоматическое выявление пропусков и уточняющие вопросы
- Генерация AS-IS описания с Mermaid-диаграммой
- Публикация HTML-страницы процесса
- Выявление точек автоматизации с inline-выбором
- Поддержка нескольких респондентов на один процесс

## UX-поток

### Принцип «одно сообщение бота»

Весь диалог бота с пользователем происходит через ОДНО сообщение бота, которое постоянно редактируется:

1. Сообщения пользователя **удаляются** после обработки.
2. Бот **не создаёт новые сообщения** — он **редактирует** существующее.
3. Прогресс, вопросы, результаты — всё отображается в одном сообщении.
4. Приветствие при создании процесса («Процесс X создан») — это **первое** сообщение бота, и оно тоже **перезаписывается** первым шагом прогресса при получении ввода от пользователя.

### Полнота описания (completeness_score)

- Полнота **никогда не уменьшается** — используется `max(старое, новое)`.
- Прогресс-бар и проценты всегда отражают монотонно растущую полноту.
- Формула: для каждого этапа проверяется наличие роли, системы, метрики, артефакта-входа и артефакта-выхода.

### Главное меню (бургер-меню → «Процессы» или /start)
- Список процессов пользователя с иконками статуса
- Кнопка «➕ Новый процесс» для создания
- По нажатию на процесс — карточка с деталями и действиями

### Создание процесса
1. Нажать «➕ Новый процесс»
2. Бот спрашивает: «Введите название процесса:»
3. Пользователь вводит название → процесс создан, интервью начинается
4. Все промежуточные сообщения удаляются

### Интервью и анализ
- Пользователь отправляет текст или голосовое сообщение
- Сообщение пользователя удаляется
- Бот редактирует одно сообщение с прогрессом (6 шагов до HTML):
  - «⏳ Записал ввод» (шаг 1/6 = 16%)
  - «⏳ Извлекаю структуру процесса» (шаг 2/6 = 33%)
  - «⏳ Формирую уточняющие вопросы» (шаг 3/6 = 50%) → переход к Q&A
  - Шаги 4-6 — генерация (см. ниже)
- Для голосовых: эффект «печатающей машинки» при отображении транскрипции
- После извлечения модели — **всегда** переход к уточняющим вопросам (без порога полноты)

### Структурные уточняющие вопросы (5-шаговый Q&A)

После первичного извлечения модели бот **всегда** запускает
**последовательный опрос из максимум 5 вопросов**. Каждый вопрос задаётся по одному,
пользователь отвечает **текстом или голосом напрямую** (без кнопки «Ответить»).
Единственная кнопка — **«Пропустить»**.

LLM генерирует вопросы на основе AS-IS модели. Для каждого вопроса LLM предлагает
свои варианты ответов (suggestions). Из ответа пользователя LLM извлекает конкретные
значения и обновляет таблицу процесса.

**Порядок вопросов (двухфазный):**

| Фаза | Категория | Когда задаётся | Что извлекается |
|------|-----------|---------------|-----------------|
| 1 | **Операции/шаги** | LLM решает, полный ли список этапов. Если да — пропускает. | Новые шаги/операции |
| 2 | **Метрики и значения** | Если есть этапы без метрик | KPI, SLA, значения метрик |
| 2 | **Роли** | Если есть этапы без owner\_role | Роли для каждого этапа |
| 2 | **Системы** | Если есть этапы без systems | Системы/инструменты |
| 2 | **Артефакты** | Если есть этапы без inputs/outputs | Документы, данные на входе/выходе |

Вопросы 2–5 генерируются **после ответа/пропуска вопроса 1** (операции), т.к. пользователь может добавить новые операции, и последующие вопросы должны их учитывать.

Номера вопросов **не показываются** пользователю — только текст вопроса и кнопка «Пропустить».

**Потоковая схема:**
1. LLM генерирует вопрос об операциях (LLM Call 2a) — показывается первым
2. После ответа/пропуска — LLM **повторно** генерирует вопросы 2–5 с `include=true/false` на основе обновлённой модели
3. Для каждого включённого вопроса:
   - Бот показывает вопрос + предложенные варианты + кнопку «Пропустить»
   - Пользователь отвечает текстом/голосом ИЛИ нажимает «Пропустить»
   - Если ответил: LLM извлекает данные из ответа (LLM Call 2b) → обновляет модель
   - Переход к следующему вопросу
4. После всех вопросов → генерация AS-IS страницы

**Промпты:**
- `bot/prompts/clarification_questions.txt` — генерация 5 вопросов
- `bot/prompts/answer_extractor.txt` — извлечение ответов из текста пользователя

### Генерация AS-IS (3 отдельных вызова LLM + публикация)

Каждый шаг — **отдельный вызов LLM**:

1. **LLM Call 3**: Текстовое описание (narrative) — `generate_narrative()`
2. **LLM Call 4**: Mermaid-диаграмма — `generate_mermaid()`
3. **Публикация HTML + PDF** — сборка narrative + diagram в HTML-шаблон через Jinja2, затем конвертация HTML→PDF через WeasyPrint
4. **LLM Call 5**: Возможности автоматизации — `generate_opportunities()`

Прогресс в том же сообщении (продолжение шагов 4-6 из 6):
- «📄 Генерирую описание процесса» (шаг 4/6 = 66%)
- «📊 Генерирую диаграмму процесса» (шаг 5/6 = 83%)
- «🌐 Публикую страницу» (шаг 6/6 = 100%)

В конце бот **редактирует сообщение** на итоговое с ссылкой на AS-IS страницу и кнопками.

### Просмотр процесса
- Нажатие на процесс в списке → карточка с:
  - Статус и процент полноты
  - Ссылка на AS-IS (если опубликован)
  - Кнопка «▶️ Продолжить заполнение» (для незавершённых)
  - Кнопка «📄 Открыть AS-IS» + «📋 Составить TO-BE» (для готовых)
  - Кнопка «← Назад» к списку

## Быстрый старт

```bash
# 1. Установить зависимости
pip install -r requirements.txt

# 2. Настроить переменные окружения
cp .env.example .env
# Заполнить .env

# 3. Запустить бота
python -m bot.main
```

## Функциональные требования (FR)

### FR-1..FR-5: Интервью
- FR-1: Сессии через уникальные deep links
- FR-2: Приём текстовых сообщений
- FR-3: Приём голосовых сообщений
- FR-4: Приём аудиофайлов
- FR-5: Хранение сырых данных с timestamp и контекстом

### FR-6..FR-8: Транскрипция
- FR-6: Whisper API для транскрипции
- FR-7: Русский язык по умолчанию
- FR-8: Обработка ошибок транскрипции

### FR-9..FR-10: Уточняющий анализ
- FR-9: После извлечения модели — всегда переход к уточняющим вопросам (без порога полноты)
- FR-10: LLM генерирует до 5 вопросов и решает какие из них задавать (include=true/false)

### FR-11..FR-17: Уточняющие вопросы (5-шаговый Q&A)
- FR-11: LLM генерирует до 5 структурных вопросов (operations, metrics, roles, systems, artifacts)
- FR-12: Вопросы 2–5 генерируются ПОСЛЕ Q1 (операции), т.к. могут быть добавлены новые операции; LLM решает какие включать (include=true/false)
- FR-13: Каждый вопрос имеет только кнопку «Пропустить»; номера вопросов НЕ показываются; пользователь отвечает текстом/голосом напрямую
- FR-14: Пропуск переходит к следующему вопросу без потери сессии
- FR-15: После ответа бот извлекает данные через LLM и обновляет AS-IS модель, затем переходит к следующему
- FR-16: Пауза и возобновление сессии
- FR-17: После всех вопросов (ответ или пропуск) — автоматический запуск генерации AS-IS

### FR-18..FR-24: Генерация AS-IS
- FR-18: HTML нарратив (LLM Call 3 — отдельный вызов)
- FR-19: Mermaid диаграмма (LLM Call 4 — отдельный вызов)
- FR-20: Публикация HTML-страницы (сборка narrative + diagram) + генерация PDF из HTML через WeasyPrint
- FR-21: URL страницы с токеном
- FR-22: Статус ASIS_PUBLISHED
- FR-23: Ссылка в чате — редактирование того же сообщения с кнопкой
- FR-24: Пошаговый прогресс генерации (шаги 1-4, одно сообщение)

### FR-25..FR-30: Автоматизация
- FR-25: Генерация opportunities (LLM Call 5 — отдельный вызов)
- FR-26: Дедупликация
- FR-27: Карточки с inline-кнопками
- FR-28: Выбор / отклонение / подробности
- FR-29: Итоговая сводка
- FR-30: Статус READY_FOR_TOBE

### FR-31..FR-33: Готовность к TO-BE
- FR-31: Кнопка «Составить TO-BE»
- FR-32: Подсчёт выбранных opportunities
- FR-33: Переход в READY_FOR_TOBE

### FR-34..FR-39: UX (чистый чат)
- FR-34: Главное меню — список процессов с кнопкой «➕»
- FR-35: Пошаговый прогресс в одном сообщении (edit, а не send+delete)
- FR-36: Удаление сообщений пользователя; бот редактирует одно своё сообщение
- FR-37: Эффект «печатающей машинки» для транскрипции
- FR-38: Бургер-меню с командой «Процессы» (/start)
- FR-39: Карточка процесса: просмотр AS-IS / продолжить заполнение / TO-BE

### FR-40..FR-43: Структурные вопросы и поток
- FR-40: Уточняющие вопросы запускаются ВСЕГДА после извлечения (нет порога полноты)
- FR-41: Вопросы задаются только о пустых полях в таблице процесса (LLM include=true/false)
- FR-42: Приоритет вопросов: операции → метрики → роли → системы → артефакты
- FR-43: Генерация AS-IS = 3 отдельных LLM-вызова (narrative, diagram, opportunities)

### FR-44..FR-47: Конфигурируемость и прогресс
- FR-44: Промпты вынесены в `bot/prompts/*.txt` — редактируются без изменения кода
- FR-45: Все статусные сообщения вынесены в `bot/messages.py`
- FR-46: Прогресс-бар показывает % до получения HTML (6 шагов: ввод→извлечение→вопросы→описание→диаграмма→публикация)
- FR-47: localhost URL не ломает Telegram inline-кнопки (показывается текстом; https — кнопкой)
- FR-48: Приветствие при создании процесса сохраняется как bot\_message\_id и перезаписывается первым прогресс-шагом

### FR-49..FR-52: Динамические вопросы, PDF, стили
- FR-49: Вопросы 2–5 генерируются после ответа/пропуска Q1 (операции), т.к. пользователь может добавить новые операции
- FR-50: Номера вопросов не показываются пользователю — только текст и кнопка «Пропустить»
- FR-51: HTML-страница конвертируется в PDF через WeasyPrint (опциональная зависимость); если WeasyPrint не установлен, PDF-генерация пропускается без ошибки
- FR-52: В секции «Последовательность процесса» заголовки шагов крупные (stage-title), между шагами отступы (stage-block), метрики по каждой операции

### FR-53..FR-58: Пагинация, автоматизация, диаграммы, прогресс
- FR-53: Главное меню показывает не более 5 процессов на странице. Навигационная строка [⬅️] [N/M] [➡️] расположена НАД кнопкой «Новый процесс». Стрелки имеют неактивное состояние (·) на крайних страницах. Если ≤5 процессов — навигация не отображается
- FR-54: Потенциал автоматизации — компактный формат: название + эмодзи типа, затем только эффект (без префикса «Эффект:»). Кнопки мультиселект (toggle ✅/⬜) с названием и эмодзи типа справа. Кнопка «Далее» появляется только при ≥1 выбранной возможности. Ссылка «Открыть AS-IS» — гиперссылка внизу сообщения
- FR-55: После нажатия «Далее» невыбранные возможности помечаются как REJECTED, процесс переходит в READY_FOR_TOBE, показывается заглушка с кнопкой «Составить TO-BE»
- FR-56: После 100% генерации (шаг 6/6) прогресс-бар удаляется и сразу показывается сообщение с потенциалом автоматизации и кнопками мультиселект (без промежуточной кнопки «Продолжить»). Ссылка на AS-IS включена в текст сообщения
- FR-57: Mermaid-диаграмма: специальные символы в метках узлов (кавычки, скобки, &, #) автоматически очищаются, чтобы избежать ошибок рендеринга
- FR-58: WeasyPrint — опциональная зависимость. Если модуль не установлен, PDF-генерация пропускается без ошибки (проверка при импорте)
