# Andre AI — Telegram-бот для анализа AS-IS процессов

Telegram-бот, который помогает компаниям описать текущие бизнес-процессы через интервью, сгенерировать AS-IS страницу и выявить возможности автоматизации.

## Возможности

- Главное меню с кнопкой «Процессы» в бургер-меню Telegram
- Создание процессов через кнопку «➕» с вводом названия
- Пошаговый прогресс при анализе (редактирование одного сообщения)
- Эффект «печатающей машинки» при отображении распознанного текста
- Автоматическое удаление сообщений пользователя и ассистента (чистый чат)
- Просмотр процесса: продолжить заполнение или открыть AS-IS/TO-BE
- Интервью по процессу через текст или голосовые сообщения
- Автоматическое выявление пропусков и уточняющие вопросы
- Генерация AS-IS описания с Mermaid-диаграммой
- Публикация HTML-страницы процесса
- Выявление точек автоматизации с inline-выбором
- Поддержка нескольких респондентов на один процесс

## UX-поток

### Принцип «одно сообщение бота»

Весь диалог бота с пользователем происходит через ОДНО сообщение бота, которое постоянно редактируется:

1. Сообщения пользователя **удаляются** после обработки.
2. Бот **не создаёт новые сообщения** — он **редактирует** существующее.
3. Прогресс, вопросы, результаты — всё отображается в одном сообщении.
4. Единственное исключение — самое первое сообщение (приветствие при создании процесса).

### Полнота описания (completeness_score)

- Полнота **никогда не уменьшается** — используется `max(старое, новое)`.
- Прогресс-бар и проценты всегда отражают монотонно растущую полноту.
- Формула: для каждого этапа проверяется наличие роли, системы, метрики, артефакта-входа и артефакта-выхода.

### Главное меню (бургер-меню → «Процессы» или /start)
- Список процессов пользователя с иконками статуса
- Кнопка «➕ Новый процесс» для создания
- По нажатию на процесс — карточка с деталями и действиями

### Создание процесса
1. Нажать «➕ Новый процесс»
2. Бот спрашивает: «Введите название процесса:»
3. Пользователь вводит название → процесс создан, интервью начинается
4. Все промежуточные сообщения удаляются

### Интервью и анализ
- Пользователь отправляет текст или голосовое сообщение
- Сообщение пользователя удаляется
- Бот редактирует одно сообщение с прогрессом (6 шагов до HTML):
  - «⏳ Записал ввод» (шаг 1/6 = 16%)
  - «⏳ Извлекаю структуру процесса» (шаг 2/6 = 33%)
  - «⏳ Оцениваю полноту описания» (шаг 3/6 = 50%)
  - Шаги 4-6 — генерация (см. ниже)
- Для голосовых: эффект «печатающей машинки» при отображении транскрипции
- После анализа — в том же сообщении: полнота и уточняющий вопрос

### Структурные уточняющие вопросы

Вопросы задаются **только о реально пустых полях** в таблице процесса. Для каждого этапа (stage) должны быть заполнены:

| Поле | Описание |
|------|----------|
| Роль (owner_role) | Кто выполняет этот шаг |
| Система (systems) | В какой системе / где происходит |
| Метрика (metrics) | Какие KPI / SLA отслеживаются |
| Артефакт-вход (inputs) | Что приходит из предыдущего шага |
| Артефакт-выход (outputs) | Что уходит в следующий шаг |

Приоритет вопросов:
1. **Шаги** — если между этапами есть разрыв, спросить о пропущенном шаге
2. **Роли** — кто выполняет шаг
3. **Системы** — где это происходит
4. **Метрики** — как измеряется
5. **Артефакты** — что на входе и выходе каждого шага

Минимум вопросов — только о реально пустых полях. Максимум 5 вопросов за раз.

### Генерация AS-IS (3 отдельных вызова LLM + публикация)

Каждый шаг — **отдельный вызов LLM**:

1. **LLM Call 3**: Текстовое описание (narrative) — `generate_narrative()`
2. **LLM Call 4**: Mermaid-диаграмма — `generate_mermaid()`
3. **Публикация HTML** — сборка narrative + diagram в HTML-шаблон через Jinja2
4. **LLM Call 5**: Возможности автоматизации — `generate_opportunities()`

Прогресс в том же сообщении (продолжение шагов 4-6 из 6):
- «📄 Генерирую описание процесса» (шаг 4/6 = 66%)
- «📊 Генерирую диаграмму процесса» (шаг 5/6 = 83%)
- «🌐 Публикую страницу» (шаг 6/6 = 100%)

В конце бот **редактирует сообщение** на итоговое с ссылкой на AS-IS страницу и кнопками.

### Просмотр процесса
- Нажатие на процесс в списке → карточка с:
  - Статус и процент полноты
  - Ссылка на AS-IS (если опубликован)
  - Кнопка «▶️ Продолжить заполнение» (для незавершённых)
  - Кнопка «📄 Открыть AS-IS» + «📋 Составить TO-BE» (для готовых)
  - Кнопка «← Назад» к списку

## Быстрый старт

```bash
# 1. Установить зависимости
pip install -r requirements.txt

# 2. Настроить переменные окружения
cp .env.example .env
# Заполнить .env

# 3. Запустить бота
python -m bot.main
```

## Структура проекта

```
bot/
├── main.py              # Точка входа
├── config.py            # Конфигурация

├── models.py            # Модели данных (SQLAlchemy)
├── states.py            # Стейт-машина
├── handlers/            # Обработчики Telegram
│   ├── start.py         # Список процессов, создание, /start
│   ├── interview.py     # Интервью с прогрессом
│   ├── clarification.py # Уточняющие вопросы
│   ├── opportunities.py # Автоматизация
│   ├── callbacks.py     # Inline-кнопки и контекст чата
│   └── progress.py      # Прогресс-сообщения и удаление
├── messages.py          # Все статусные сообщения (для редактирования)
├── prompts/             # LLM-промпты (отдельные .txt файлы)
│   ├── extractor.txt    # Промпт извлечения AS-IS модели
│   ├── gap_detector.txt # Промпт детекции пропусков
│   ├── generator.txt    # Промпт генерации описания
│   ├── mermaid.txt      # Промпт генерации диаграммы
│   └── opportunities.txt# Промпт генерации автоматизаций
├── services/            # Бизнес-логика
│   ├── llm.py           # LLM-клиент
│   ├── transcription.py # Транскрипция аудио
│   ├── extractor.py     # Извлечение AS-IS модели (LLM Call 1)
│   ├── gap_detector.py  # Детектор пропусков (LLM Call 2)
│   ├── generator.py     # Генерация AS-IS нарратива (LLM Call 3)
│   ├── mermaid.py       # Генерация Mermaid-диаграммы (LLM Call 4)
│   ├── opportunities.py # Генерация точек автоматизации (LLM Call 5)
│   └── publisher.py     # Сборка HTML и публикация
└── templates/
    └── asis_page.html   # HTML-шаблон страницы
pages/                   # Опубликованные страницы
```

## Функциональные требования (FR)

### FR-1..FR-5: Интервью
- FR-1: Сессии через уникальные deep links
- FR-2: Приём текстовых сообщений
- FR-3: Приём голосовых сообщений
- FR-4: Приём аудиофайлов
- FR-5: Хранение сырых данных с timestamp и контекстом

### FR-6..FR-8: Транскрипция
- FR-6: Whisper API для транскрипции
- FR-7: Русский язык по умолчанию
- FR-8: Обработка ошибок транскрипции

### FR-9..FR-10: Детекция пропусков
- FR-9: Оценка полноты (completeness_score) — монотонно возрастает
- FR-10: Генерация уточняющих вопросов (gaps) — структурные, по этапам

### FR-11..FR-17: Уточняющие вопросы
- FR-11: Inline-кнопки «Ответить» / «Пропустить» / «Завершить позже»
- FR-12: Ответ на вопрос как текст или голос
- FR-13: Пропуск вопроса
- FR-14: Пауза сессии
- FR-15: Возобновление сессии
- FR-16: Порог полноты для генерации AS-IS
- FR-17: Лимит уточняющих вопросов

### FR-18..FR-24: Генерация AS-IS
- FR-18: HTML нарратив (LLM Call 3 — отдельный вызов)
- FR-19: Mermaid диаграмма (LLM Call 4 — отдельный вызов)
- FR-20: Публикация HTML-страницы (сборка narrative + diagram)
- FR-21: URL страницы с токеном
- FR-22: Статус ASIS_PUBLISHED
- FR-23: Ссылка в чате — редактирование того же сообщения с кнопкой
- FR-24: Пошаговый прогресс генерации (шаги 1-4, одно сообщение)

### FR-25..FR-30: Автоматизация
- FR-25: Генерация opportunities (LLM Call 5 — отдельный вызов)
- FR-26: Дедупликация
- FR-27: Карточки с inline-кнопками
- FR-28: Выбор / отклонение / подробности
- FR-29: Итоговая сводка
- FR-30: Статус READY_FOR_TOBE

### FR-31..FR-33: Готовность к TO-BE
- FR-31: Кнопка «Составить TO-BE»
- FR-32: Подсчёт выбранных opportunities
- FR-33: Переход в READY_FOR_TOBE

### FR-34..FR-39: UX (чистый чат)
- FR-34: Главное меню — список процессов с кнопкой «➕»
- FR-35: Пошаговый прогресс в одном сообщении (edit, а не send+delete)
- FR-36: Удаление сообщений пользователя; бот редактирует одно своё сообщение
- FR-37: Эффект «печатающей машинки» для транскрипции
- FR-38: Бургер-меню с командой «Процессы» (/start)
- FR-39: Карточка процесса: просмотр AS-IS / продолжить заполнение / TO-BE

### FR-40..FR-43: Структурные вопросы и монотонность
- FR-40: Полнота (completeness_score) никогда не уменьшается — `max(old, new)`
- FR-41: Вопросы задаются только о пустых полях в таблице процесса
- FR-42: Приоритет вопросов: шаги → роли → системы → метрики → артефакты
- FR-43: Генерация AS-IS = 3 отдельных LLM-вызова (narrative, diagram, opportunities)

### FR-44..FR-47: Конфигурируемость и прогресс
- FR-44: Промпты вынесены в `bot/prompts/*.txt` — редактируются без изменения кода
- FR-45: Все статусные сообщения вынесены в `bot/messages.py`
- FR-46: Прогресс-бар показывает % до получения HTML (6 шагов: ввод→извлечение→полнота→описание→диаграмма→публикация)
- FR-47: localhost URL не ломает Telegram inline-кнопки (показывается текстом; https — кнопкой)
